# Release 1.18.0 — Antigravity Global Rules Manager (Settings Inline Editor for ~/.gemini/GEMINI.md)

## English

### Overview of Changes

- **Feature Goal:** Add a self-service **"Antigravity Global Rules"** card to the Monitor's **Settings** tab so users can view, open, locate, edit and save Antigravity's machine-global rules file (`~/.gemini/GEMINI.md`) without leaving the panel — on **both** the Antigravity IDE extension and the Antigravity App native Sidecar UI, following the project's zero-patch, zero-external-dependency philosophy.
- **Why `~/.gemini/GEMINI.md`:** Antigravity inherits the Gemini CLI configuration convention (the same convention this project already relies on for `~/.gemini/config/config.json` and `~/.gemini/config/plugins/`). The global rules Markdown file lives at `<homedir>/.gemini/GEMINI.md` and is applied by Antigravity to **every agent conversation across every workspace**. Workspace-scoped rules (`.gemini/GEMINI.md`, `.agent/rules/`) are intentionally out of scope — the card only ever touches the machine-global file.

#### New Pure-Node Module (`src/global-rules.ts`)

- **Zero `vscode` imports** so the module is shared verbatim by the IDE extension, the App Sidecar runtime, and unit tests (same pattern as `orchestrator-attribution.ts` and `durable-state.ts`).
- **`getGlobalRulesPath(homedir?)`** — resolves `<home>/.gemini/GEMINI.md` (falls back to `os.homedir()`; explicit homedir support keeps tests hermetic via `os.tmpdir()` sandboxes).
- **`readGlobalRulesStatus({ homedir?, includeContent? })`** — stat + capped UTF-8 read returning a `GlobalRulesStatus { path, exists, sizeBytes, content, tooLarge }` snapshot. Ordinary failure modes (missing file, unreadable path) resolve to `exists: false` snapshots instead of throwing, so every caller can render the Settings card without try/catch. Files larger than `GLOBAL_RULES_MAX_BYTES` (1 MiB) are reported with `tooLarge: true` and **empty** content — the file is never truncated or partially loaded into the textarea.
- **`writeGlobalRulesFile(content, homedir?)`** — validates `Buffer.byteLength(content) <= GLOBAL_RULES_MAX_BYTES` **before any disk mutation**, recursively creates the `~/.gemini/` parent when missing, then writes UTF-8. Oversized payloads throw with a descriptive message, guaranteeing an oversized textarea save can never clobber an existing rules file.
- **`DEFAULT_GLOBAL_RULES_TEMPLATE`** — bilingual starter (`# Global Rules` + EN/ZH HTML comments) used by the IDE "Open File" flow when the file does not exist yet.

#### New Settings Card (`src/webview-settings-tab.ts`)

- `SettingsTabOptions.globalRules?: GlobalRulesStatus | null` — hosts may inject a fresh snapshot; when omitted the card **lazily computes** one via `readGlobalRulesStatus()` (keeping every existing caller working with zero host changes), and explicit `null` hides the card entirely (useful for embedders/tests).
- Card layout mirrors the existing *Persistent Storage* card for a consistent editorial look:
  - `.stg-header` with the `ICON.file` glyph and bilingual title **"Antigravity Global Rules" / "Antigravity 全局规则"**.
  - A `.raw-desc` explainer: what the file is, where it lives, and that it applies to all workspaces.
  - A `.storage-path-box` with the absolute path (`#globalRulesPathText`, `esc()`-escaped, ellipsized) plus a bilingual **Ready / Missing** state pill (`#globalRulesState`) carrying machine-readable `data-gr-exists` / `data-gr-too-large` attributes.
  - A `.storage-actions` row with four buttons — **Open File** (`#globalRulesOpenBtn`), **Reveal** (`#globalRulesRevealBtn`), **Reload** (`#globalRulesReloadBtn`), **Save** (primary-styled `#globalRulesSaveBtn`) — and the dedicated `#globalRulesFeedback` live region (`role="status"`).
  - The inline editor `#globalRulesEditor` (`spellcheck="false"`, HTML-escaped content via `esc()`, localized placeholder; oversized files show a "edit externally" placeholder with an empty, still-safe textarea).
  - `.storage-stat-grid` tiles: live **File Size** (`#globalRulesSizeVal`) and an **All workspaces** scope tile, followed by a `stg-hint-note` clarifying the 1 MiB cap and the "never touches workspace rules" safety guarantee.
- Inserted directly below the *Persistent Storage* card in the Settings tab on both surfaces (`surface: 'ide'` and `surface: 'app-sidecar'`).
- `MonitorDocumentBuildParams.globalRules` (`src/webview-document.ts`) forwards host-provided snapshots into `buildSettingsContent()`.

#### IDE Host Wiring (`src/webview-panel.ts`)

- Four new webview message handlers in the existing `onDidReceiveMessage` chain:
  - **`readGlobalRulesFile`** → replies `{ command: 'globalRulesFileContent', ok: true, ...status }`.
  - **`saveGlobalRulesFile`** → byte-length pre-check (bilingual oversize error), `writeGlobalRulesFile()`, replies `{ command: 'globalRulesSaveResult', ok, sizeBytes, path }`.
  - **`openGlobalRulesFile`** → creates the file from `DEFAULT_GLOBAL_RULES_TEMPLATE` when missing, then opens it in the editor via the existing `openUriInEditor()`; replies `globalRulesActionResult` (`action: 'open'`).
  - **`revealGlobalRulesFile`** → `revealFileInOS` on the file, or its `~/.gemini/` parent directory when missing.
- New `reportGlobalRulesError()` helper mirrors `reportStateFileError()`: bilingual `showWarningMessage` + structured failure messages back to the webview so the inline feedback region explains what went wrong.

#### App Sidecar Host Wiring (`src/app/sidecar-runtime.ts`)

- The same four commands are served by the authenticated loopback `/api/action` bridge (`handleAction` switch), returning VS Code-compatible `messages` arrays plus inline `result` payloads so the shared client script works unchanged across surfaces:
  - `readGlobalRulesFile` → `{ ok: true, result: status, messages: [globalRulesFileContent] }`.
  - `saveGlobalRulesFile` → strict `typeof action.content === 'string'` guard, `400` on missing content, `413` on oversize, `500` with sanitized message on write failure.
  - `openGlobalRulesFile` / `revealGlobalRulesFile` → resolves the rules path, falls back to the parent directory when the file is missing, validates via the existing `validateRevealTargetPath()` (realpath + traversal + scheme guards) and reveals through `deps.revealInOs()`.
- **Reveal-root allowlist update (`getAllowedRevealRoots()`):** added `~/.gemini/` itself alongside the existing `~/.gemini/antigravity`, `~/.gemini/config`, durable-state directory and workspace URIs. The global rules file sits directly under `~/.gemini/`, so reveal/open requires that root; every other path outside the allowlist remains forbidden and symlink-escape protection is unchanged.
- Read/save/open/reveal actions never mutate `AppSettings` or the durable state file — they are pure file operations on `~/.gemini/GEMINI.md`.

#### Client Script Wiring (`src/webview-script.ts`)

- New bilingual status variables (`grReloadingText`, `grSavingText`, `grSaveFailedText`, `grLoadFailedText`) alongside the existing settings-script strings.
- Click-delegation handlers for the four buttons follow the established dual-path pattern (`bridge.surface !== 'vscode' && typeof bridge.sendAction === 'function'` → Sidecar HTTP bridge, else `vscode.postMessage`):
  - **Save** disables the button while pending, sends the full textarea content, and restores it on completion (immediately on the bridge path, via the `globalRulesSaveResult` message on the IDE path).
  - **Reload** fills the textarea from the returned snapshot (skipping content when `tooLarge`) and refreshes the size tile + state pill.
  - **Open / Reveal** flash `Opening... / Revealing...` then `✓ Opened / ✓ Revealed` (or the host's error text).
- `updateGlobalRulesMeta(payload)` keeps `#globalRulesSizeVal` and `#globalRulesState` in sync from any of the three message channels (`globalRulesFileContent`, `globalRulesSaveResult`, `globalRulesActionResult`); its byte formatting mirrors `webview-helpers.formatFileSize` exactly.
- The message listener gained handlers for all three channels, so IDE-originated flows flash the same feedback as Sidecar bridge responses.

#### Styling (`src/webview-styles.ts`)

- New `.stg-globalrules-editor` block styled exclusively with existing editorial theme variables (`--ed-surface-well`, `--ed-control-border`, `--ed-mono`, `--ed-accent`, `--ed-radius-sm`, `--ed-ink`, `--ed-ink-muted`): monospace 12px/1.55, vertical resize (180–420px), `:focus-visible` accent border, muted placeholder, and a dimmed disabled state — Dark / Light / High-Contrast themes inherit automatically with zero new color literals.

### 更新概览

- **功能目标：** 在监控面板的**设置**选项卡中新增自服务的 **「Antigravity 全局规则」** 卡片，让用户无需离开面板即可查看、打开、定位、编辑并保存 Antigravity 的机器级全局规则文件（`~/.gemini/GEMINI.md`）——同时覆盖 **Antigravity IDE 扩展**与 **Antigravity App 原生 Sidecar** 两端，完整延续本项目「零补丁、零外部依赖」的设计哲学。
- **为什么是 `~/.gemini/GEMINI.md`：** Antigravity 沿用 Gemini CLI 的配置约定（本项目此前读取 `~/.gemini/config/config.json` 与 `~/.gemini/config/plugins/` 时已采用同一约定）。全局规则 Markdown 文件位于 `<用户目录>/.gemini/GEMINI.md`，会被 Antigravity 应用于**所有工作区的所有智能体会话**。工作区级规则（`.gemini/GEMINI.md`、`.agent/rules/`）刻意不在本卡片范围内——卡片只会触碰机器级全局文件。

#### 全新纯 Node 模块（`src/global-rules.ts`）

- **零 `vscode` 依赖**，模块被 IDE 扩展、App Sidecar 运行时与单元测试原样共享（与 `orchestrator-attribution.ts`、`durable-state.ts` 的组织方式一致）。
- **`getGlobalRulesPath(homedir?)`** — 解析 `<home>/.gemini/GEMINI.md`（缺省回退 `os.homedir()`；显式 homedir 参数让测试可基于 `os.tmpdir()` 沙箱完全隔离）。
- **`readGlobalRulesStatus({ homedir?, includeContent? })`** — stat + 限量 UTF-8 读取，返回 `GlobalRulesStatus { path, exists, sizeBytes, content, tooLarge }` 快照。常规失败场景（文件缺失、路径不可读）返回 `exists: false` 快照而非抛错，所有调用方无需 try/catch 即可渲染设置卡片；超过 `GLOBAL_RULES_MAX_BYTES`（1 MiB）的文件标记 `tooLarge: true` 并返回**空**内容——文件绝不会被截断或部分载入文本域。
- **`writeGlobalRulesFile(content, homedir?)`** — 在**任何磁盘变更之前**校验 `Buffer.byteLength(content) <= GLOBAL_RULES_MAX_BYTES`，缺失时递归创建 `~/.gemini/` 父目录，随后以 UTF-8 写入。超限内容抛出带描述的错误，确保超大文本域保存永远不会破坏既有规则文件。
- **`DEFAULT_GLOBAL_RULES_TEMPLATE`** — 双语起始模板（`# Global Rules` + 中英 HTML 注释），供 IDE「打开文件」流程在文件尚不存在时创建使用。

#### 全新设置卡片（`src/webview-settings-tab.ts`）

- `SettingsTabOptions.globalRules?: GlobalRulesStatus | null` — 宿主可注入最新快照；省略时卡片通过 `readGlobalRulesStatus()` **惰性计算**（既有调用方零改动即可工作），显式传 `null` 可完全隐藏卡片（便于嵌入方与测试）。
- 卡片布局与既有 *持久化存储* 卡片一致，保持编辑主题观感：
  - `.stg-header` 使用 `ICON.file` 图标与双语标题 **"Antigravity Global Rules" / "Antigravity 全局规则"**。
  - `.raw-desc` 说明文字：文件是什么、位于哪里、对所有工作区生效。
  - `.storage-path-box` 展示绝对路径（`#globalRulesPathText`，经 `esc()` 转义、超宽省略）与双语 **已存在 / 不存在** 状态胶囊（`#globalRulesState`），携带机器可读的 `data-gr-exists` / `data-gr-too-large` 属性。
  - `.storage-actions` 行内四个按钮——**打开文件**（`#globalRulesOpenBtn`）、**定位文件**（`#globalRulesRevealBtn`）、**重新加载**（`#globalRulesReloadBtn`）、**保存**（主样式 `#globalRulesSaveBtn`）——以及独立的 `#globalRulesFeedback` 实时反馈区（`role="status"`）。
  - 内联编辑器 `#globalRulesEditor`（`spellcheck="false"`，内容经 `esc()` HTML 转义，本地化占位符；超大文件显示「请使用外部编辑器」占位符，文本域保持空白且安全）。
  - `.storage-stat-grid` 统计瓦片：实时**文件大小**（`#globalRulesSizeVal`）与**全部工作区**作用范围瓦片，随后 `stg-hint-note` 说明 1 MiB 上限与「绝不修改工作区规则」安全保证。
- 在 IDE（`surface: 'ide'`）与 App Sidecar（`surface: 'app-sidecar'`）两端的设置页中均紧随 *持久化存储* 卡片渲染。
- `MonitorDocumentBuildParams.globalRules`（`src/webview-document.ts`）将宿主注入的快照透传至 `buildSettingsContent()`。

#### IDE 宿主接线（`src/webview-panel.ts`）

- 在既有 `onDidReceiveMessage` 处理链中新增四个 webview 消息处理器：
  - **`readGlobalRulesFile`** → 回执 `{ command: 'globalRulesFileContent', ok: true, ...status }`。

  - **`openGlobalRulesFile`** → 文件缺失时先用 `DEFAULT_GLOBAL_RULES_TEMPLATE` 创建，再经既有 `openUriInEditor()` 在编辑器中打开；回执 `globalRulesActionResult`（`action: 'open'`）。
  - **`revealGlobalRulesFile`** → 对文件执行 `revealFileInOS`，缺失时定位其 `~/.gemini/` 父目录。
- 新增 `reportGlobalRulesError()` 助手，镜像 `reportStateFileError()`：双语 `showWarningMessage` + 结构化失败消息回传 webview，让内联反馈区明确解释失败原因。

#### App Sidecar 宿主接线（`src/app/sidecar-runtime.ts`）

- 同样四个命令由带鉴权的本地回环 `/api/action` 桥接（`handleAction` switch）提供，返回 VS Code 兼容的 `messages` 数组与内联 `result` 载荷，共享客户端脚本跨端零改动：
  - `readGlobalRulesFile` → `{ ok: true, result: status, messages: [globalRulesFileContent] }`。

- 读/写/打开/定位动作不会改动 `AppSettings` 或持久化状态文件——纯粹针对 `~/.gemini/GEMINI.md` 的文件操作。

#### 客户端脚本接线（`src/webview-script.ts`）

- 在既有设置脚本文案旁新增双语状态变量（`grReloadingText`、`grSavingText`、`grSaveFailedText`、`grLoadFailedText`）。
- 四个按钮的点击委托沿用既定双通道模式（`bridge.surface !== 'vscode' && typeof bridge.sendAction === 'function'` → Sidecar HTTP 桥，否则 `vscode.postMessage`）：
  - **保存**在等待期间禁用按钮、发送完整文本域内容，完成后恢复（桥通道立即恢复；IDE 通道通过 `globalRulesSaveResult` 消息恢复）。
  - **重新加载**以返回快照填充文本域（`tooLarge` 时跳过内容填充）并刷新大小瓦片与状态胶囊。

- 消息监听器新增三个通道的处理器，IDE 侧流程与 Sidecar 桥响应呈现一致的反馈权体验。

#### 面板内一键自更新与手动压缩包安装（Antigravity App）

1. **面板内自更新：** 打开 **设置 → 版本更新** 或 **关于 → 版本与更新**，点击 **检查更新**，再点击 **立即升级**。校验通过的原子替换完成后，打开 `[Antigravity Context Monitor](customization://antigravity-context-monitor)` 并将插件 **关闭再重新开启**（绝不强杀运行中的 Antigravity 会话）。
2. **手动压缩包安装：** 下载 `antigravity-context-monitor-app-1.18.0.zip`（macOS / Windows / Linux）或 `antigravity-context-monitor-app-1.18.0.tar.gz`（macOS / Linux）与 `SHA256SUMS.txt`，核对 SHA-256 摘要，解压（`antigravity-context-monitor/`）后运行 `agy plugin install ./antigravity-context-monitor`（或直接解压到 `~/.gemini/config/plugins/` 或 `%USERPROFILE%\.gemini\config\plugins\`）。

#### Antigravity IDE（VSIX 扩展 — macOS / Windows / Linux / WSL）

下载 `antigravity-context-monitor-1.18.0.vsix`（对照 `SHA256SUMS.txt` 核验 SHA-256），在命令面板执行 **Extensions: Install from VSIX...**（`Cmd+Shift+P` / `Ctrl+Shift+P`）或：

```bash
antigravity-ide --install-extension antigravity-context-monitor-1.18.0.vsix --force
```

重载 IDE 窗口，并在扩展详情或 **关于** 中确认版本为 **1.18.0**（也可通过 [Open VSX](https://open-vsx.org/extension/AGI-is-going-to-arrive/antigravity-context-monitor) 安装）。

#### 使用全新的全局规则卡片

1. 打开监控面板 → **设置** 选项卡 → **Antigravity 全局规则** 卡片（位于 *持久化存储* 下方）。
2. 确认路径胶囊（`~/.gemini/GEMINI.md`，**已存在** 或 **不存在**）。
3. 直接在文本域编辑后点击 **保存**（上限 1 MiB、UTF-8），或点击 **打开文件** 用外部编辑器修改——在 IDE 端，文件缺失时会先用双语起始模板创建。
4. 外部修改后点击 **重新加载** 刷新文本域、大小瓦片与状态胶囊。规则会在**新建**的 Antigravity 智能体会话中生效。
