# Release 1.17.10 — Fix Windows Inline TopBar WCO Gap & Anchoring Hardening

## English

### Overview of Changes

- **Fixed Windows Inline TopBar WCO Blank Gap & Hardened `computeWcoInsetPx` Boundary Guards (credits: [`@Number444`](https://github.com/Number444), [Issue #77](https://github.com/AGI-is-going-to-arrive/Antigravity-Context-Window-Monitor/issues/77) — `CDP_OVERLAY_SCRIPT_VERSION = '1.17.10'` — `src/app/cdp-overlay-assets.ts`):**
  - **Eliminated phantom inline `.acm-wco-spacer` gap (`computeWcoInsetPx(isFixedAnchor)`):** Returns `0` immediately whenever `!isFixedAnchor`, preventing inline Top-Right Status Bar hosts (`right-overlay` and `pane-titlebar-toolbar`) from wedging a ~146px blank spacer (~151px including the `5px` `:host` gap) between `.acm-bar-cluster` and adjacent native controls (such as `toggle-aux-sidebar`) on Windows Antigravity 2.35.2's two-row header layout (where Row 1 holds `_ □ ×` and Row 2 holds the conversation header without a `window-controls-reserve` node).
  - **Hardened `fixed`-mode `computeWcoInsetPx(true)` boundary checks:** `findVisibleTopRightWcoReserve()` scans `document.querySelectorAll(reserveSel)` for the first visible top-**right** reserve (`resRect.top < 48 && resRect.width > 0 && resRect.width < vw * 0.5 && resRect.right >= vw - 60`), preventing both hidden `legacy-window-controls-reserve` nodes and top-left reserves (such as macOS traffic-light or Windows RTL reserves) from adding false right-edge spacers; requires `rect && typeof rect.right === 'number' && rect.right > 0` and `rightGap < vw * 0.5` so Chromium's transitional empty `DOMRect(0,0,0,0)` never inflates spacer width to `vw + 8`; and returns `0` authoritatively when `wco.visible && rect.right > 0 && rightGap === 0` so Windows Fullscreen / RTL layouts never fall through to the `138px` Windows default fallback.
- **Row-Accurate Inline Right-Chrome Budgeting, Empty Row-1 WCO Cutout Guard, Idempotent Anchoring & Live `geometrychange` (`src/app/cdp-overlay-assets.ts`):**
  - **Fixed companion Windows 2.35.2 premature `···` collapse (`getRightChromeLeftPx()`):** Stopped subtracting phantom `computeWcoInsetPx(true)` from `vw - 10` when anchored inline (previously losing ~120–146px of free width on Row-2 headers); inspects visible following element siblings of `state.topBarHost` in `parentElement` on the same row first (for both `right-overlay` and `pane-toolbar`) and scans inline right-chrome controls up to `r.top < 96` (accurately budgeting Row-2 buttons at `top >= 48` with `AUX_PANE` open or closed), while retaining `vw - 10 - computeWcoInsetPx(true)` and `r.top < 48` strictly for `fixed` mode.
  - **Empty Row-1 `pane-titlebar-toolbar` WCO cutout guard (`findTopBarAnchor()` Tier 3):** Skips an empty `pane-titlebar-toolbar` (zero visible element children besides `state.topBarHost` and no visible `window-controls-reserve`) when it vertically and horizontally overlaps the right WCO cutout (`wco.visible`, `wcoRect.right > 0`, `tbRect.top < wcoBottom && tbRect.bottom > wcoTop`, content-box right edge `tbContentRight > wcoRect.right`, with safe `getComputedStyle` fallback), falling through cleanly to Tier 4 `fixed` so inline pills never collide with Windows/Linux `_ □ ×` buttons while Row-2 or right-padded toolbars remain inline with `0px` spacer.
  - **Idempotent `anchor.before` normalization & `windowControlsOverlay` `geometrychange` listener:** Normalized self-referential `anchor.before === host` to `host.nextSibling` in `anchorTopBarHost()` and `anchorComposerHost()` so repeat update ticks in Tier 3 `pane-toolbar` and Composer fallback tiers are strictly idempotent instead of calling `insertBefore(host, host)` or triggering needless popover repositions; added a guarded `navigator.windowControlsOverlay` `geometrychange` listener (removed cleanly in `unmountSlot('all')`) to keep `fixed` WCO insets synced across fullscreen, DPI, and WCO visibility transitions.
  - **Live session hot-swap:** Bumped `CDP_OVERLAY_SCRIPT_VERSION` to `'1.17.10'` so live CDP sessions automatically unmount `'1.17.9'` overlays and hot-swap the hardened script.

### 更新概览

- **修复 Windows 内联右上角状态条 WCO 多余空白并加固 `computeWcoInsetPx` 边界守卫（致谢 [`@Number444`](https://github.com/Number444)，[Issue #77](https://github.com/AGI-is-going-to-arrive/Antigravity-Context-Window-Monitor/issues/77) — `CDP_OVERLAY_SCRIPT_VERSION = '1.17.10'` — `src/app/cdp-overlay-assets.ts`）：**
  - **消除内联幽灵 `.acm-wco-spacer` 空白（`computeWcoInsetPx(isFixedAnchor)`）：** 当 `!isFixedAnchor` 时立即返回 `0`，彻底防止内联挂载的右上角状态条（`right-overlay` 与 `pane-titlebar-toolbar`）在 Windows Antigravity 2.35.2 双行标题栏布局下（第一行承载 `_ □ ×`，第二行承载会话顶栏且不挂载 `window-controls-reserve`）于 `.acm-bar-cluster` 与相邻原生按钮（如 `toggle-aux-sidebar`）之间插入约 146px 的多余空白占位（含 `5px` `:host` 间距约 151px）。
  - **加固 `fixed` 模式 `computeWcoInsetPx(true)` 边界校验：** `findVisibleTopRightWcoReserve()` 改为遍历 `document.querySelectorAll(reserveSel)` 查找首个可见的右**上角**预留节点（`resRect.top < 48 && resRect.width > 0 && resRect.width < vw * 0.5 && resRect.right >= vw - 60`），避免被前置隐藏的 `legacy-window-controls-reserve` 阻断，并防止 macOS 交通灯或 Windows RTL 左上角预留区误触发右侧留白；增加 `rect && typeof rect.right === 'number' && rect.right > 0` 与 `rightGap < vw * 0.5` 校验，彻底防止 Chromium 过渡期空 `DOMRect(0,0,0,0)` 将留白宽度误算为 `vw + 8`；在 `wco.visible && rect.right > 0 && rightGap === 0` 时直接权威返回 `0`，避免 Windows 全屏或 RTL 布局错误回退到 `138px` Windows 默认兜底值。
- **内联同行右侧控件宽度预算、空首行 `pane-toolbar` WCO 区域防碰撞、幂等锚定与 `geometrychange` 实时监听（`src/app/cdp-overlay-assets.ts`）：**
  - **修复 Windows 2.35.2 伴随的过早 `···` 折叠问题（`getRightChromeLeftPx()`）：** 内联模式下不再从 `vw - 10` 错误扣减 `computeWcoInsetPx(true)`（此前会令第二行顶栏可用宽度虚缩约 120–146px）；改为优先读取 `state.topBarHost` 同一 `parentElement` 内可见后续兄弟元素的最小 `left`（兼顾 `right-overlay` 与 `pane-toolbar`），并将内联右侧控件扫描纵向范围扩展至 `r.top < 96`（准确识别 `top >= 48` 的第二行按钮及 `AUX_PANE` 展开/收起状态），仅在 `fixed` 模式下保留 `vw - 10 - computeWcoInsetPx(true)` 与 `r.top < 48`。
  - **空首行 `pane-titlebar-toolbar` WCO 区域防碰撞守卫（`findTopBarAnchor()` Tier 3）：** 当 `pane-titlebar-toolbar` 除 `state.topBarHost` 外不含任何可见原生子元素且无可见 `window-controls-reserve`，同时纵向与横向内容右缘均落入右侧 WCO 窗口按钮区域（`wco.visible`、`wcoRect.right > 0`、`tbRect.top < wcoBottom && tbRect.bottom > wcoTop`、`tbContentRight > wcoRect.right`，安全兼容 `getComputedStyle`）时，自动跳过 Tier 3 并平滑回退至 Tier 4 `fixed` 模式避让 Windows/Linux `_ □ ×` 按钮，同时确保第二行或带右内边距工具栏继续保持内联与 `0px` 留白。
  - **幂等 `anchor.before` 自引用归一化与 `windowControlsOverlay` `geometrychange` 监听：** 在 `anchorTopBarHost()` 与 `anchorComposerHost()` 中将自引用 `anchor.before === host` 归一化为 `host.nextSibling`，使 Tier 3 `pane-toolbar` 与输入框回退层级的重复刷新严格幂等，不再调用 `insertBefore(host, host)` 或触发多余弹窗重定位；注册受保护的 `navigator.windowControlsOverlay` `geometrychange` 监听器（并在 `unmountSlot('all')` 完整移除），在全屏、DPI 或 WCO 几何切换时实时同步 `fixed` 留白。
  - **活跃会话自动热替换：** 将 `CDP_OVERLAY_SCRIPT_VERSION` 递增至 `'1.17.10'`，活跃 CDP 会话会自动卸载 `'1.17.9'` 悬浮层并无感热替换为加固后的新脚本。

#### 面板内一键自更新与手动压缩包安装（Antigravity App）

1. **面板内自更新（v1.17.6+）：** 打开**设置 → 更新**或**关于 → 版本与更新**，点击**检查更新**并点击**立即升级**。原子替换完成后，打开 `[Antigravity Context Monitor](customization://antigravity-context-monitor)` 将插件**关闭再重新开启**即可安全加载新运行时（绝不强杀正在运行的 Antigravity 会话）。
2. **手动压缩包安装：** 下载 `antigravity-context-monitor-app-1.17.10.zip`（macOS / Windows / Linux）或 `antigravity-context-monitor-app-1.17.10.tar.gz`（macOS / Linux）与 `SHA256SUMS.txt`，核对 SHA-256 后解压得到 `antigravity-context-monitor/` 并执行 `agy plugin install ./antigravity-context-monitor`（或直接解压至 `~/.gemini/config/plugins/` 或 `%USERPROFILE%\.gemini\config\plugins\`）。

#### 可选 CDP 桌面悬浮层与一键持久化启动器（严格按需开启，零二进制修改）

核心 `AUX_PANE`、`SIDEBAR` 与**原生面板精简 HUD** 均 100% 原生工作，不依赖 CDP。若您按需启用输入框上下文环或右上角状态条 4 视图悬浮层：

- **推荐方案（一键持久化，永久免疫自动更新丢参）：** 在**设置 → 悬浮层与 CDP** 点击**一键生成持久化启动器**（或运行 `node scripts/install-app-plugin.mjs --setup-cdp-launcher`），自动生成 `~/Applications/Antigravity (CDP).app`（macOS）、桌面与开始菜单 `.lnk`（Windows）或 `~/.local/share/applications/antigravity-cdp.desktop`（Linux），点击设置页的**在访达 / 资源管理器 / 文件夹中显示**即可一键定位。
- **手动终端重启：**
  1. **务必先完全退出 Antigravity App**（macOS 按 `Cmd+Q` 后请等待约 5 秒让后台 `language_server` 彻底清理完成——旧进程尚未退出时执行 `open -a` 会静默忽略 `--args`；Windows / Linux 关闭全部窗口与托盘图标）。
  2. **带 `--remote-debugging-port=0` 参数重新启动：**
     - **macOS（无竞态等待并启动）：** `while pgrep -f '^/Applications/Antigravity\.app/Contents/MacOS/Antigravity($| )' >/dev/null; do sleep 0.5; done; open -a "/Applications/Antigravity.app" --args --remote-debugging-port=0`
     - **Windows（PowerShell）：** `& "$env:LOCALAPPDATA\Programs\Antigravity\Antigravity.exe" --remote-debugging-port=0`
     - **Windows (CMD / 快捷方式目标)：** `"%LOCALAPPDATA%\Programs\Antigravity\Antigravity.exe" --remote-debugging-port=0`
     - **Linux：** `antigravity --remote-debugging-port=0`
  3. 打开**设置 → 悬浮层与 CDP** 点击**重新检测**。

#### Antigravity IDE（VSIX 扩展 — macOS / Windows / Linux / WSL）

下载 `antigravity-context-monitor-1.17.10.vsix`（对照 `SHA256SUMS.txt` 校验 SHA-256），在命令面板（`Cmd+Shift+P` / `Ctrl+Shift+P`）执行 **Extensions: Install from VSIX...**，或命令行运行：

```bash
antigravity-ide --install-extension antigravity-context-monitor-1.17.10.vsix --force
```

重载 IDE 窗口，在扩展详情或**关于**页确认版本号为 **1.17.10**（亦可从 [Open VSX](https://open-vsx.org/extension/AGI-is-going-to-arrive/antigravity-context-monitor) 获取更新）。
