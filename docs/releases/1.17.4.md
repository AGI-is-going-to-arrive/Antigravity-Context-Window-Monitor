# Release 1.17.4 — Status Bar Hover Flicker Fix & Discovery / Quota Hardening

## English

### Overview of Changes

- **Status Bar Hover Tooltip flicker fix (3-layer elimination):** Fixed the recurring 5-second hover tooltip disappear/reappear blink caused by unconditional `StatusBarItem` property assignments triggering VS Code IPC `$setEntry` updates where `markdownStringEqual()` always fails strict object-reference equality (`a.isTrusted === b.isTrusted`) on `MarkdownString.isTrusted = { enabledCommands: [...] }` and disposes/recreates the visible hover widget:
  - **Diff-guarded `StatusBarItem` commits (`src/statusbar.ts`):** Consolidated all mutable `StatusBarItem` writes (`name`, `backgroundColor` by `ThemeColor.id`, `text`, `accessibilityInformation` `label` + `role`, and `tooltip` by rendered Markdown string) into diff-guarded commit paths (`commitName()` / `renderStatus()`), while keeping the strict `isTrusted` command allowlist (`antigravity-context-monitor.showDetails`, `antigravity-context-monitor.refresh`) intact. Unchanged renders perform **zero** `StatusBarItem` setter writes and zero IPC `$setEntry` calls.
  - **Caller-side deduplication & state hygiene (`src/extension.ts`):** Added structural equality checking (`hasAuxiliaryMetadataChanged()`) in `triggerLiveAuxiliaryMetadataRefresh()` so unchanged 10-second `OrchestratorSettings`/`UserQuotaSummary` refreshes skip redundant status bar & WebView updates; fixed the `!hadUiSummary` double-render bug (`!hadUiSummary && gmTracker.getUiSummary() !== null`) when GM UI summary is still absent; stopped 5–15s disconnected `Initializing` ↔ `Disconnected` ping-pong on background retries while keeping immediate `Initializing` feedback on explicit manual `Refresh` (`pollContextUsage(isManualRefresh = false)`); and moved compression detection ahead of `statusBar.update()` so compression renders in one pass.
  - **Stabilized monotonic countdowns (`src/statusbar.ts`):** Captured one `nowMs` snapshot per render, aligned positive countdowns to wall-clock minutes with ±45s per-pool `resetTime` jitter hysteresis (`stabilizeResetMinute()`, bounded per-render `pruneStabilizedResetKeys()`, cleared on account switch/reconnect/`dispose()`), eliminating staggered multi-pool minute ticks, `0m` / `2m → 0m` skips, and backward jitter jumps across the 60s boundary while preserving immediate `Ready` / bar-clear transitions on exact expiry (`rawResetMs <= nowMs`).
- **Secondary-port TLS-first discovery & `GetUserStatus` object validation (credits: `@AxelDZP`, PR #74):** Updated `probeProcess()` (`src/discovery.ts`) so `agy --hub` continues probing declared `--hub-port` or primary `hintPort` over HTTP first, while secondary ports enumerated via `lsof` / `ss` / `netstat` after a primary port fails probe **HTTPS/TLS first** — eliminating spurious `HTTP 400` / Go `http: TLS handshake error` logs on paired TLS hub ports across Windows, macOS, Linux, and IPv6 `[::1]`. Tightened `GetUserStatus` response validation in both `probeEndpoint()` (`src/discovery.ts`) and `fetchFullUserStatus()` (`src/tracker.ts`) to require a non-null, non-array `userStatus` object (rejecting `{}`, `null`, `[]`, and soft-200 error payloads).
- **Strict RFC 3339 / ISO-8601 epoch-0 & chronological pool reset handling (credits: `@AxelDZP`, PR #74):** Exported `parseStrictResetTimestamp()` (`src/tracker.ts`) with strict RFC 3339 timestamp, leap-year, calendar-date, and timezone-offset validation (recognizing equivalent proto3 epoch-0 forms such as `1970-01-01T00:00:00.000Z` and `1970-01-01T00:00:00+00:00`, while rejecting loose `Date.parse` inputs like `'0'`, `'1970'`, `'0bad'`, `'2026-02-30T00:00:00Z'`, and invalid offsets) and aligned `src/model-quota.ts` (`readQuota()`). Applied `parsePositivePoolResetMs()` and chronological `comparePoolResetTimes()` (`src/extension.ts`) across `groupModelConfigsByQuotaPool()`, `updateAccountSnapshot()`, `shouldSettleOnResetTimeChange()`, `baselineExpiredPoolsForAccount()`, proactive `DailyLedger` settlement, `checkCachedAccountResets()`, and `StatusBarManager`, ensuring epoch-0 or malformed dates never trigger premature settlement or sort ahead of valid reset timestamps.

### 更新概览

- **修复状态栏悬停摘要闪烁（三层根治）：** 彻底修复每隔 5 秒悬停摘要短暂消失并重现的问题（根因是轮询周期无条件写入 `StatusBarItem` 属性，触发 VS Code IPC `$setEntry` 传输后 `markdownStringEqual()` 对 `MarkdownString.isTrusted = { enabledCommands: [...] }` 的对象引用判等恒为 `false`，从而销毁并重建当前悬停浮层）：
  - **全属性差异门控提交（`src/statusbar.ts`）：** 将全部可变属性（`name`、按 `ThemeColor.id` 比对的 `backgroundColor`、`text`、`accessibilityInformation` 的 `label` 与 `role`、以及按渲染后 Markdown 字符串比对的 `tooltip`）收敛至差异门控路径（`commitName()` / `renderStatus()`），同时完整保留严格的 `isTrusted` 命令白名单（`antigravity-context-monitor.showDetails`、`antigravity-context-monitor.refresh`）。内容未变时执行 **0** 次属性写入、发出 **0** 次 IPC `$setEntry` 更新。
  - **调用方去重与状态防抖（`src/extension.ts`）：** 在 `triggerLiveAuxiliaryMetadataRefresh()` 中新增结构化变更比对（`hasAuxiliaryMetadataChanged()`），10 秒周期拉取的 `OrchestratorSettings` / `UserQuotaSummary` 无变化时跳过冗余状态栏与面板刷新；修复无 GM 摘要时 `!hadUiSummary` 导致的双渲染（改为 `!hadUiSummary && gmTracker.getUiSummary() !== null`）；消除断连后台重试期间每 5–15 秒 `Initializing` ↔ `Disconnected` 来回闪烁，同时在手动点击**刷新**时保留即时 `Initializing` 反馈（`pollContextUsage(isManualRefresh = false)`）；并将压缩检测前移至 `statusBar.update()` 之前，实现单阶段更新。
  - **单调稳定的倒计时（`src/statusbar.ts`）：** 单次渲染共用统一 `nowMs` 快照，对未来重置时间执行分钟边界对齐与每池 ±45 秒 `resetTime` 抖动迟滞（`stabilizeResetMinute()`、逐帧 `pruneStabilizedResetKeys()`、账号切换/重连/`dispose()` 清空），彻底消除多配额池错峰跳变、`0m` / `2m → 0m` 跳档及 60 秒边界附近的倒退抖动，并保持到期瞬间（`rawResetMs <= nowMs`）立即切换为 `就绪` / 清除倒计时。
- **次要端口 TLS 优先探测与 `GetUserStatus` 结构校验（致谢 `@AxelDZP`，PR #74）：** 升级 `probeProcess()`（`src/discovery.ts`），对 `agy --hub` 声明的 `--hub-port` 或主 `hintPort` 维持 HTTP 优先，主端口失败后经 `lsof` / `ss` / `netstat` 枚举的次要端口改为 **HTTPS/TLS 优先探测**，消除 Windows、macOS、Linux 及 IPv6 `[::1]` 配对 TLS 端口的 `HTTP 400` / Go `http: TLS handshake error` 噪声；并在 `probeEndpoint()`（`src/discovery.ts`）与 `fetchFullUserStatus()`（`src/tracker.ts`）中强制校验 `userStatus` 为非 null 非数组对象（拒绝 `{}`、`null`、`[]` 与软 200 错误体）。
- **严格 RFC 3339 / ISO-8601 纪元零值与按时间顺序排序的配额池重置处理（致谢 `@AxelDZP`，PR #74）：** 在 `src/tracker.ts` 导出严格解析器 `parseStrictResetTimestamp()`（严格校验 RFC 3339 格式、闰年、真实日历日期与时区偏移，统一识别 `1970-01-01T00:00:00.000Z` / `1970-01-01T00:00:00+00:00` 等价 proto3 纪元零值，拒绝 `'0'`、`'1970'`、`'0bad'`、`'2026-02-30T00:00:00Z'` 与非法偏移等宽松 `Date.parse` 输入），并同步收紧 `src/model-quota.ts`（`readQuota()`）；同时将 `parsePositivePoolResetMs()` 与按 UTC 毫秒排序的 `comparePoolResetTimes()`（`src/extension.ts`）贯通至 `groupModelConfigsByQuotaPool()`、`updateAccountSnapshot()`、`shouldSettleOnResetTimeChange()`、`baselineExpiredPoolsForAccount()`、`DailyLedger` 主动结算、`checkCachedAccountResets()` 与 `StatusBarManager`，防止纪元零值或异常时间戳触发提前结算或排在有效重置时间之前。
