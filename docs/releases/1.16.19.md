# 1.16.19 — Gemini 4 Argon, Image Models, and IDE Compatibility

Release date: 2026-10-31

## English

Antigravity Context Window Monitor 1.16.19 supports Gemini 4 Argon Low / Medium / High with official dated API pricing, verifies the current 13 chat variants, adds the separate image-generation catalog, and fixes monitoring in Antigravity IDE builds using the `agy` hub backend.

### Gemini 4 Argon

| Effort | Internal ID | Catalog ID |
| --- | --- | --- |
| Low | `MODEL_PLACEHOLDER_M419` | `gemini-4-argon-low` |
| Medium | `MODEL_PLACEHOLDER_M418` | `gemini-4-argon-medium` |
| High | `MODEL_PLACEHOLDER_M417` | `gemini-4-argon-high` |

A metadata-only probe of the running IDE on 2026-10-31 verified all three identities through `GetUserStatus` and `GetAvailableModels`. Each catalog entry reports:

- Google Gemini provider, 1,048,576-token IDE-reported model context, and 65,536-token maximum output.
- A 256,000-token platform compression limit and a separate 50,000-token checkpointer threshold. The static fallback is 255,000 until live metadata arrives.
- Thinking support, with effort levels 1 / 2 / 3 for Low / Medium / High. The reported minimum thinking budget of 32 is a capability boundary, not a fixed per-request thinking budget.

Placeholder IDs, catalog IDs, English labels, and Chinese effort labels resolve to the same identities. The three effort identities remain distinct in context tracking, GM data, and saved history, while sharing the Gemini quota pool. The Models tab uses the signed-in account's live picker; Gemini 3.x, Claude 5.5/4.6, and other historical identities remain supported. Family-only response names do not overwrite an explicitly selected effort tier.

Quota rows prefer the current model, then a live recommended model, then the newest available model generation. Integer versions such as Gemini 4 rank correctly alongside decimal versions, without pinning the Gemini pool to an older Flash model.

### Official Gemini 4 Argon pricing

The [Google Standard API pricing table](https://ai.google.dev/gemini-api/docs/pricing#gemini-4-argon), verified 2026-10-31, applies the following USD rates per million tokens to all effort tiers:

| Call date (UTC) | Input | Output, including thinking | Implicit cache reads |
| --- | ---: | ---: | ---: |
| Through 2026-11-30 | $2.00 | $10.00 | $0.10 |
| From 2026-12-01 | $4.00 | $20.00 | $0.20 |

The rate is selected using each call's UTC timestamp; historical usage does not switch to December prices merely because it is viewed later. Existing archival totals and custom overrides are preserved. Argon supports implicit caching only, so no explicit cache-write charge is added. These are Standard API equivalents, not Batch/Flex/Priority prices or Antigravity subscription charges and credits. Unknown models still retain explicit missing-price handling.

Independent image quota is unavailable, so image generation is not assigned a chat quota pool. An omitted image thinking flag displays **Not reported by IDE**, rather than **Not supported**.

The actual image workflow returned no separate M21 token, credit, or GM usage. The Cost tab therefore shows known subtotals and explicitly excludes image-generation fees, with the official pricing link; it does not report image generation as free. Linked image-generation steps are counted without merging child text tokens into the parent context.

### Context and telemetry correctness

- Current `agy` responses can report precise `modelUsage` on planner-response steps without any `CHECKPOINT`. The monitor now reads those values while preserving legacy checkpoint support, and reads the selected effort tier from user-input planner configuration before the first response.
- Provider-reported fresh input, cache-read, cache-creation, and output counts all contribute to context and take precedence over GM `estimatedTokensUsed`. Cache hits therefore do not reduce measured context or falsely trigger compression. Estimates are never relabeled as precise. Pre-upgrade usage caches are invalidated, and running steps are re-fetched even when summary counts have not changed.
- GM capacity uses `cwm.maxContextTokens` when the legacy planner threshold is absent. Successful entries in retry telemetry no longer create duplicate retry counts.
- The empty status shows **No active conversation**, without reusing a persisted model's denominator. The dashboard header wraps at narrow widths, fixing overlapping controls at 320 px.
- Current Gemini 3.8 Flash picker tiers now use the verified 50,000 checkpointer trigger and thinking levels 1 / 2 / 3, with no fixed budget. Complete live catalog records clear obsolete protobuf-default thinking metadata; incomplete records preserve known values. The archived `M322` router and older generations retain their historical profiles.

### `LS not found` fix

The current IDE launches `agy --hub` (or `agy.exe` on Windows), rather than a process named `language_server_*`. It also uses equals-separated options such as `--hub-port=<port>` and `--csrf_token=<token>`. The previous discovery path could not identify that process or parse its token, even though the backend was running.

Discovery now supports the hub architecture alongside legacy language servers. It recognizes the backend executable, hub flags, and Antigravity data-directory marker; parses both equals-separated and space-separated arguments, including quoting and Windows CSV escaping; validates declared ports; and probes the local Connect-RPC service. Stale candidates do not prevent later candidates from being checked. When the IDE supplies a connection hint, discovery stays bound to that instance instead of selecting another running IDE/account. Platform-specific socket discovery and legacy Windows, macOS, Linux, and WSL paths remain available. Tokens are used locally for authentication and are not included in diagnostic output. The current-IDE hint comes from the already active built-in extension; the monitor does not activate it or another extension to obtain the connection.

A connected backend may return no loaded trajectories while saved conversations still exist in IDE history. This displays **No active conversation**, not `LS not found` or a stale model limit. Opening the IDE without a project does not by itself make the backend unavailable. Missing/lost-backend tooltips now support English, Chinese, and bilingual modes, including immediate refresh when the display language changes.

### 上下文与遥测准确性

- 当前 `agy` 可在 planner-response 步骤直接返回精确 `modelUsage`，无需 `CHECKPOINT`。监控器现已读取这些值，同时保留旧版 checkpoint 支持；首次回复前即可从用户输入的 planner 配置识别所选思考档位。
- 提供商报告的新输入、缓存读取、缓存创建和输出均计入上下文，优先于 GM 的 `estimatedTokensUsed`；缓存命中不会因此低估上下文或误报压缩。估算不会被标为精确。升级前的用量缓存会失效，运行中的步骤即使摘要数量不变也会重新拉取。
- GM 缺少旧版 planner 阈值时，从 `cwm.maxContextTokens` 获取容量；重试遥测中的成功条目不再造成重复重试计数。
- 空状态显示**无活跃会话**，不沿用历史模型的分母。监控面板顶部在窄宽度下自动换行，修复 320 px 时控件重叠。
- 当前 Gemini 3.8 Flash picker 三档同步采用已核实的 50,000 checkpointer 触发阈值和 1 / 2 / 3 思考力度，不设置固定预算。完整实时目录会清除已过时的 protobuf 默认思考字段；不完整记录保留已知值。归档的 `M322` 路由及较旧世代保留历史画像。

### 修复 `LS not found`

当前 IDE 启动的是 `agy --hub`（Windows 为 `agy.exe`），不再是名为 `language_server_*` 的进程，同时使用 `--hub-port=<port>`、`--csrf_token=<token>` 等等号分隔参数。旧发现逻辑无法识别该进程或解析其 token，因此后端正常运行时仍会报错。

发现逻辑现在同时支持 hub 架构和旧版语言服务器，识别后端可执行文件、hub 参数及 Antigravity 数据目录标记，兼容等号、空格分隔参数、引号和 Windows CSV 转义，校验声明端口，并探测本地 Connect-RPC 服务。失效候选不会阻止检查后续候选；IDE 提供连接提示时，发现范围限定为对应实例，不会转而连接其他 IDE/账号。平台套接字发现和旧版 Windows、macOS、Linux、WSL 路径继续保留。Token 仅用于本地鉴权，不写入诊断输出。当前 IDE 的连接提示来自已经激活的内置扩展，监控器不会为了获取连接而主动激活该扩展或其他扩展。

后端连接成功后，已加载的 trajectory 列表可能为空，而 IDE 历史中仍保存着对话。此时显示**无活跃会话**，而非 `LS not found` 或过时的模型上限。IDE 未打开项目也不代表后端不可用。未发现/失去后端连接的 tooltip 现已支持英文、中文、双语，并在显示语言切换时立即刷新。

### 安装

通过 **Extensions: Install from VSIX...** 安装 `antigravity-context-monitor-1.16.19.vsix`，随后重载当前 Antigravity IDE 窗口。在扩展详情中确认版本为 **1.16.19**，打开 **模型** 页，并通过 **Output → Antigravity Context Monitor** 查看发现诊断。命令面板快捷键为 macOS 的 `Cmd+Shift+P` 和 Windows/Linux 的 `Ctrl+Shift+P`。
